# OCI application engineering

`oci-application-engineering` is the application-code orchestrator. It performs intake and data classification, local knowledge and reuse discovery, read-only plugin evaluation, test-driven implementation, independent review, security verification, and optional adaptive MultiLLM measurement. It performs no OCI mutation.

MultiLLM is an opt-in local gateway integration. Offer it for side-by-side model comparison, cheap-first routing, independent Fusion synthesis, cost/latency traces, or the separate DeepEval end-to-end suite; never require it, enable it, transmit code to it, or install providers without the user's explicit choice. When it is unavailable or declined, continue with the primary agent and record a skipped optional measurement gate.

Offline development is not a blocked OCI action. Generate application code,
tests, reviews, module-reuse decisions, documentation, and local validation
without a tenancy preflight or OCI CLI help lookup; identify the future live
resource owner only when the work reaches deployment.

Search DevVisualization and the current repository before external packages. Keep restricted code local unless external-provider approval is explicit. Plugins are recommendations only until the user approves installation. Platform bundles remain `oci-product-development`, delivery services remain `oci-developer-services`, and independent AppSec release gates remain `oci-security-compliance`.
