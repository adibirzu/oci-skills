What “more capable” should mean

Better routing, less trial and error

A weather forecast currently routes to OCI cost; a leaked-secret rotation query finds no skill. Add domain confidence, calibrated abstention, negative cases, natural paraphrases and safe multi-service handoffs.

Portable operations, not inherited incident assumptions

Remove universal assumptions about exactly five flow logs, 100% sampling and amd64-only Functions. Discover real topology, architecture, retention and budget. Keep incident-specific recipes opt-in.

Optional OCI AI with the same safety boundaries

The current provider envelope disables invocation. Add governed retrieval, intent normalization or explanation only where measured benefit exists. Keep deterministic offline operation, regional discovery, data controls, bounded cost and explicit action authorization.

Test actual outcomes across installed harnesses

Structural contracts are not service acceptance. Test packaged tasks, failures, resume and rollback, then run separately authorized provider canaries and independent held-out agent trials.

Measure token savings, do not infer them from disk size

Compare baseline and candidate using the same task, harness, model and starting state. Measure actual input/cached/output tokens, first-attempt success, failed calls, human turns and latency. Accept savings only without safety or success regressions.

Delivery sequence and exit criteria

Make distribution safe

Transactional installer, license, secret transport, green CI.

Exit: no payload loss or secret leakage in failure tests.

B · Consistency

Make guidance portable

Routing, architecture-aware recipes, truthful gates and generated docs.

Exit: realistic routing tests and no generic incident-specific mutations.

C · Execution

Prove workflows

Typed plans, durable receipts, safe resume and installed-bundle conformance.

Exit: supported harnesses pass outcome and rollback tests.

D / E · Expansion

Integrate, then accept

Optional OCI AI, prioritized provider journeys, provenance and independent evaluation.

Exit: approved canaries and measured token/retry improvements.

Recommended decision

Retain the 29-capability architecture and official Oracle specialist handoffs. Fix the release blockers first. Then improve the common workflow contract and documentation across every skill before adding new service breadth. No claim of universal customer readiness or Google-tool parity is justified yet.
